# 006-DOCUMENT_STRUCTURE.md
# リポジトリ構造 不変規範（強制版・汎用）

本ルールはリポジトリ全体の構造を固定するための強制規範である。  
すべてのAgent・人間は従う。

---

# 1. 第一階層は役割軸のみ

リポジトリ直下は「役割」で分ける。

例：

- apps/        → 実行単位
- packages/    → 共有ライブラリ
- docs/        → 設計・仕様
- tools/       → 補助スクリプト
- scripts/     → 実行用スクリプト
- infra/       → インフラ定義
- tests/       → 横断テスト

機能軸・フェーズ軸を第一階層に置かない。

---

# 2. 分類軸は途中で変更しない

途中で：

- フェーズ軸へ変更
- 機能軸へ変更
- 集約目的の再分類

を禁止する。

構造変更は「全体再設計宣言」がある場合のみ許可。

---

# 3. apps/ ルール

apps/ 直下は「実行可能単位」のみ。

禁止：
- v1 / v2
- new / old
- temp / test-app
- フェーズ名

生成物（dist/build/tmp）は置かない。

---

# 4. docs/ ルール

- `docs/100-PROJECT/` を正本とする。仕様・方針・制約は必ずここを基準とする。
 - 101 または 108 に明示されていない仕様変更はすべて変更要求とみなす。変更要求は必ず 108 に追記してから実装する。
- docs/ は単一分類軸のみ。(`docs/100-PROJECT/` 以外)
- 分類軸は `docs/100-PROJECT/101-README_PROJECT.md`に記載
- 分類軸が未確定/未記入の場合は、`docs/` への新規ファイル追加を禁止する。
- `docs/`配下に作成するディレクトリ（core/ mod/等）・ファイルは 100-PROJECT の展開であること。100-PROJECT と矛盾してはならない。


---

# 5. packages/ ルール

packages/ は「再利用単位」のみ。

機能ごとの細分化は禁止。  
アプリ専用コードは置かない。

---

# 6. 新規ディレクトリ作成条件

作成前に確認：

1. 既存役割に収まらないか？
2. 将来10倍に増えても破綻しないか？
3. 分類軸を壊していないか？

YESでなければ作成しない。

---

# 7. 例外処理

例外は：

- 理由を明文化
- 影響範囲を明示
- 将来の扱い方針を書く

無記録の例外は禁止。

---

# 8. Agent禁止事項

Agentは禁止：

- 暗黙の軸変更
- 部分的再分類
- 曖昧フォルダ作成
- 単一ファイルの例外扱い
- フェーズ名ディレクトリ作成

---

# 最重要原則

整理より一貫性を優先する。  
局所最適より構造安定性を優先する。
