# 100-COMPLETENESS_GATE.md

## 目的
`docs/100-PROJECT/` 配下の記入状態を判定し、
Agent / Sprint / リリース開始可否を統一する。

---

# 基本構造（3フェーズ）

本プロジェクトは **三軸運用** を採用する。

- Phase ＝ 文書成熟度（プロジェクト全体の前提）
- Sprint ＝ 実装サイクル（反復）
- MVP ＝ Phase 2 の完了条件（内部達成）
  - 外部公開可能状態は Phase 3 で担保する

---

# Phase 定義（3段階）

## Phase 1（設計確立）
目的：MVPの「範囲」と「境界」を確定する（実装は最小に抑える）
許可：設計・調査・PoC（必要最小限）
禁止：本格実装の開始（MVP実装はPhase 2）

## Phase 2（MVP実装）
目的：MVPを動作可能な状態として達成する（内部達成）
許可：MVP実装、必要テスト、API契約の確定
完了：MVP機能が動作し、必要テストが通り、運用上の入口が揃う

## Phase 3（リリース準備・安定化）
目的：外部公開（運用）可能性を担保する
許可：E2E、運用Runbook整備、リリース判定
完了：リリースゲート通過

# 開始ゲート（Agent共通）

Agent は作業開始前に本表を確認する。

## 停止条件（必須）
- `101-README_PROJECT.md` 未記入 → 即停止
- Phase 2 以降で必須文書が未記入 → 停止
- 「API着手」「実装着手」「Phase 3（公開準備）」に該当するのに対象文書が未記入 → 停止

停止時は不足文書を明示し、人間に確認を依頼する。

---

# Sprint 運用ルール（Phase連携）

## Sprint開始前（必須）
1. `108-SPRINT_STATUS.md` を更新：
   - Sprint目標
   - 対象範囲
   - 対象TID
   - 未解決リスク
   - 「今回がPhase 1/2/3のどれか」を明記

2. Phaseに応じた必須文書の充足確認
3. 対象機能に対応する設計文書の存在確認（不足なら実装に入らない）

---

## Sprint終了時
- `108-SPRINT_STATUS.md` を更新（完了/継続/次Sprint）
- Phase 2 では「MVP達成状況（達成/未達/残課題）」を記録する
- Phase 3 では `112-E2E_CHECKLIST.md` の実施状況を記録する

---

# MVP達成の定義（Phase 2完了条件）

Phase 2 の完了（MVP達成）は、最低限次を満たすこと：

- MVPスコープの機能が動作する（入口がある）
- 必要なテストが通過している（最低限の自動テスト or 検証手順がある）
- APIを提供する場合は契約が確定している（`109`）
- 命名・サニタイズ規範が適用されている（`110`/`111`）
- `108-SPRINT_STATUS.md` に MVP達成が明記されている

---

# 設計意図
- Phase 2 で MVP を達成し、Phase 3 で公開可能性を担保する。
- Phase と Sprint を直交させ、混乱を防ぐ。
