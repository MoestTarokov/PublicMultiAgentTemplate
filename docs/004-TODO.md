# TODO運用（正本）

## 状態
- `[ ]` 未着手
- `[~]` 進行中
- `[x]` 完了（対応コミット済み）
- `[!]` ブロック中

遷移:
- 開始: `[ ] -> [~]`
- 完了: `[~] -> [x]`（最終コミットで確定）
- 障害: `[~] -> [!]`
- 再開: `[!] -> [~]`

補足（状態の意味）:
- `[~]` は「実行中（in-flight）」を表す
- `[!]` は「停止中（ブロック/無応答）」を表す
- 監視側の `timed_out` は `[!]` への即時遷移理由にしない（継続中の可能性を優先）

## 進捗メタ情報（記号仕様は変更しない）
`[ ]/[~]/[!]/[x]` は維持し、必要な進捗情報は行末タグで補助する。

推奨タグ:
- `owner=<agent-id>`
- `hb=<ISO8601>`
- `retry=<n>`
- `note=<short-reason>`
- `retry` は再委譲が確定した時点で `+1` 更新する

記載例:
```text
- [~] #TID-3-2-1 [worker] API実装 {owner=worker-a hb=2026-03-04T11:20+09:00 retry=0}
```

## 規範
- 作業開始前にタスク登録
- TID は `tools/tid_assigner.py` で採番
- コード/契約/テスト/設定変更は孫タスクまで分割
- 孫タスクがコミット単位
- docs-only でもコミット必須
- 親/子は直下が全て `[x]` のとき完了伝播

非実装ロール（explorer/researcher/reviewer）は TODO を直接編集しない。
必要な更新は root が代行する。

## 粒度目安（固定値ではなくガイド）
- fast_worker 向け: 10〜30分、1〜3ファイル、1責務
- worker 向け: 20〜60分、3〜8ファイル、1責務
- 60分超見込み、または責務2つ以上は孫タスクを分割する
- 例外は root が理由・影響を明記して許可する

## 孫タスク標準手順
1. 対象孫タスクを `[~]` に更新
2. `[~]` 行に `owner` と初回 `hb` を付与
3. 実装/調査を実施（長時間時は `hb` 更新）
4. ブロック時は `[!]` に更新し `note` を付与
5. 完了時に `[x]` 更新
6. `git add`
7. `commit_linter` 実行
8. `git commit`（`#TID` 必須）
9. `git status --porcelain` 確認

## 最終回答前ゲート
- `[x]` の TID に対応コミットが存在
- 未コミット差分が残っていない
- `AGENTOUTPUT.md` / `MEMORY.md` は root のみ更新

 - [ ] #TID-1-1 [Agent] 子タスク
  - [ ] #TID-1-1-1 [Agent] 孫タスク
